## 1) Primitive components (atoms)

I’ll assume these core tokens by name (from Palette A + type system):

* **Colors**

  * `color-bg-dark` = Night Purple (`#2D2246`)
  * `color-bg-darker` = Soup Shadow (`#1A132E`)
  * `color-bg-light` = Paper Lavender (`#F7F6FF`)
  * `color-accent-primary` = Primordial Purple (`#7E44F1`)
  * `color-accent-secondary` = Cyan Highlight (`#6ADDDD`)
  * `color-border-subtle` = Lavender Mist (`#BBB0F7`)
  * `color-text-on-dark` = `#FFFFFF`
  * `color-text-on-light` = Mono Ink (`#000000`)
  * `color-text-muted-dark` = Lavender Mist (`#BBB0F7`)
* **Typography**

  * `font-display-condensed` = Founders Grotesk X-Condensed
  * `font-sans` = Founders Grotesk
  * `font-mono` = Fira Mono
* **Spacing**

  * `space-xs` 4px, `space-sm` 8px, `space-md` 12–16px,
    `space-lg` 24px, `space-xl` 32px, `space-2xl` 48px
* **Radius**

  * `radius-sm` 6px, `radius-lg` 12px, `radius-pill` = full

### 1.1 Button

* **Purpose**
  Primary and secondary CTAs like “Contact us”, in a quiet, editorial style.

* **Content slots / props**

  * `label` (text)
  * `variant`: `primary`, `secondary`, `ghost`
  * `tone`: `dark-surface` (on dark bg), `light-surface` (on light bg)
  * `size`: `sm`, `md`
  * `hasArrow`: boolean (adds subtle arrow glyph, not an icon icon set)

* **Tokens**

  * Colors:

    * Primary: `color-accent-primary` background, `color-text-on-dark` text.
    * Secondary: transparent bg, `color-accent-primary` text, `color-border-subtle` border.
    * Ghost: fully transparent, text uses `color-text-on-dark` or `color-text-on-light`.
  * Typography: `font-sans`, `font-size-sm/md`, medium weight.
  * Spacing: `space-sm` vertical, `space-md` horizontal.
  * Radius: `radius-pill`.

---

### 1.2 TextLink

* **Purpose**
  Inline or standalone text CTAs like “See how we value a catalog →”.

* **Content slots / props**

  * `label`
  * `href` / `onClick`
  * `emphasis`: `default`, `quiet`
  * `withArrow`: boolean

* **Tokens**

  * Colors: `color-accent-primary` or `color-text-on-dark` with underline; hover shifts to slightly lighter purple tint.
  * Typography: `font-sans`, `font-size-sm/md`.
  * Spacing: minimal; mainly text-level.

---

### 1.3 EyebrowLabel

* **Purpose**
  Tiny section labels like “About Primordial”, “The Primordial System”.

* **Content slots / props**

  * `text`
  * `tone`: `light-on-dark`, `dark-on-light`

* **Tokens**

  * Typography: `font-mono`, `font-size-xs`, letter-spacing slightly expanded.
  * Color:

    * On dark bg: `color-text-muted-dark`
    * On light bg: `color-bg-dark`
  * Spacing: bottom margin `space-xs` before title.

---

### 1.4 SectionTitle

* **Purpose**
  Main headline for each section.

* **Content slots / props**

  * `text`
  * `level`: `hero`, `section`
  * `align`: default `left`

* **Tokens**

  * Typography:

    * `hero`: `font-display-condensed`, very large, tight leading.
    * `section`: `font-sans` bold, `font-size-xl`.
  * Color:

    * On dark: `color-text-on-dark`
    * On light: `color-bg-dark`
  * Spacing: top margin `space-lg`–`space-xl`, bottom margin `space-sm`–`space-md`.

---

### 1.5 SectionSubtitle

* **Purpose**
  One-line secondary title or framing sentence under the main title.

* **Content slots / props**

  * `text`
  * `tone`: `neutral`, `highlight` (slightly stronger)

* **Tokens**

  * Typography: `font-sans`, `font-size-md`, regular weight.
  * Color: muted form of text (on dark: modulate toward `color-text-muted-dark`; on light: slightly reduced opacity of `color-bg-dark`).
  * Spacing: top margin `space-xs`, bottom `space-sm`.

---

### 1.6 BodyText

* **Purpose**
  Paragraph content for narrative sections.

* **Content slots / props**

  * `children` (rich text)
  * `size`: `md`, `sm`
  * `tone`: `default`, `muted`

* **Tokens**

  * Typography: `font-sans`, `font-size-md/sm`, regular weight.
  * Color:

    * Default: `color-text-on-light` or `color-text-on-dark` as appropriate.
    * Muted: slightly lowered opacity or use `color-text-muted-dark` on dark.
  * Spacing: line-height slightly loose (editorial), paragraph spacing `space-sm`.

---

### 1.7 BulletList

* **Purpose**
  For lists in Product Highlight, Rights Holders, Investors.

* **Content slots / props**

  * `items`: array of `{ title?: string, body: string }`
  * `style`: `plain` (standard bullets) or `titled` (title + short body)

* **Tokens**

  * Typography: `font-sans`, `font-size-md`.
  * Color: same as BodyText.
  * Spacing: `space-xs` between items, `space-sm` between groups.
  * Custom bullet: small square or en dash in `color-accent-primary` instead of default dot.

---

### 1.8 MonoMetaText

* **Purpose**
  For margin notes, nav labels, section index like `Thesis`, `Funds & Buyers`.

* **Content slots / props**

  * `text`
  * `placement`: `inline`, `margin-left`, `margin-right`, `header`

* **Tokens**

  * Typography: `font-mono`, `font-size-xs/sm`, uppercase optional.
  * Color: muted (Lavender Mist on dark; `color-bg-dark` at lower opacity on light).
  * Spacing: small; used as secondary layer.

---

### 1.9 Divider / Rule

* **Purpose**
  Thin visual separators, including vertical margin rules.

* **Content slots / props**

  * `orientation`: `horizontal`, `vertical`
  * `length`: `full`, `content`
  * `emphasis`: `subtle`, `strong`

* **Tokens**

  * Color: `color-border-subtle` for subtle; slightly deeper tint for strong.
  * Thickness: 1px.
  * Spacing: `space-md` above/below horizontal lines.

---

### 1.10 PillTag

* **Purpose**
  For small labels (e.g. potential hex swatches, feature tags, but used sparingly).

* **Content slots / props**

  * `label`
  * `tone`: `light`, `dark`
  * `hasSwatch`: boolean (small circle at start using accent color)

* **Tokens**

  * Color:

    * Light: Paper Lavender background, `color-bg-dark` text.
    * Dark (on Soup background): `color-bg-darker` background, `color-text-on-dark` text.
  * Typography: `font-sans`, `font-size-xs`.
  * Spacing: horizontal padding `space-sm`, vertical `space-xs`.
  * Radius: `radius-pill`.

### 2.1 HeroSection

* **Purpose**
  Opening scene with Giant M Horizon, core positioning, and main CTA.

* **Content slots**

  * `eyebrow` (EyebrowLabel)
  * `title` (SectionTitle level=hero)
  * `subtitle` (SectionSubtitle)
  * `aboutLine` (short BodyText)
  * `primaryCTA` (Button)
  * `secondaryLink` (TextLink)
  * `headerNav` (logo + nav links, MonoMetaText for labels)

* **Layout rules**

  * Single centered column (~720px), **content left-aligned**.
  * Hero column sits in the left ~30–40% of the visual horizon; background M occupies right side.
  * Vertical spacing: very airy — generous space above title and between blocks.

* **Motifs**

  * Background: Giant gradient **M** rising from bottom-right, obeying logo/M rules (clean cyan→purple gradient, no noise).
  * Ground color: Poster Black / Night Purple.
  * No other shapes: no cards, no icons; just type + giant M.

  Text-led chapter with a title, a couple of paragraphs, maybe a short supporting line.

* **Content slots**

  * `eyebrow` (optional)
  * `title`
  * `subtitle` (optional)
  * `body` (1–3 BodyText blocks)
  * `metaLabel` (MonoMetaText margin note, e.g. `Thesis`)

* **Layout rules**

  * Same centered column; text fully left-aligned.
  * Eyebrow → Title → Subtitle → Body, stacked vertically.
  * Optional vertical rule on left side of the column, with the meta label pinned to it.

* **Motifs**

  * Background typically flat or very soft gradient:

    * e.g. dark background with almost imperceptible Soup band at bottom.
  * No M foregrounds; keep this section mostly typographic to let the story breathe.

## 3) Usage guidelines

I’ll group guidelines per **type** to keep this readable.

---

### Buttons & TextLinks

**Do**

* Use **primary Button** sparingly (hero, final CTA); keep others as TextLinks to maintain editorial feel.
* Pair TextLinks with arrows for scroll-based anchors (e.g. “See how we value a catalog →”).
* On dark backgrounds, ensure sufficient contrast by using `color-text-on-dark` and clear focus states.

**Don’t**

* Don’t create multi-button clusters (“Get started” / “Book a demo” / “Sign up free”) — one main action is enough.
* Don’t add icons or pictograms into buttons; that pushes toward generic SaaS.
* Don’t use bright cyan/pink as button fills; those stay as **accents** in gradients, not CTA colors.

---

### EyebrowLabel, SectionTitle, SectionSubtitle

**Do**

* Use EyebrowLabel consistently at the top of each section to create a clear narrative spine.
* Keep SectionTitles short and concrete, e.g. “Acquire with conviction”, not long sentences.
* Use Subtitle sparingly, mainly when you need a single clarifying line.

**Don’t**

* Don’t over-style eyebrows (no backgrounds, no pill shapes); they should stay quiet, typographic.
* Don’t mix multiple title styles in the same section; choose either hero or normal section title.
* Don’t center-align titles; maintain left alignment for editorial consistency.

---

### BodyText & BulletList

**Do**

* Keep paragraphs short (2–4 lines) and separated with `space-sm` to preserve the memo-like feel.
* Use BulletList when clarity benefits from structure (system items, benefits), not for everything.
* Use **titled bullets** (“Data — …”) instead of icons to keep it on-brand.

**Don’t**

* Don’t create dense walls of text; if a paragraph exceeds 5–6 lines, break it.
* Don’t mix multiple bullet styles; choose one bullet style across the page.
* Don’t use emojis or heavy decorative bullets; stick with simple, understated marks.

---

### MonoMetaText & Divider / Rule

**Do**

* Use MonoMetaText for small labels in margins (`Thesis`, `Creators`, `Funds & Buyers`) to add editorial structure.
* Use vertical Dividers sparingly to guide the eye up/down a section.
* Keep MetaText short (1–2 words) and consistent in tone.

**Don’t**

* Don’t use MonoMetaText for primary content; it’s for annotations only.
* Don’t spam vertical rules; one per major section is enough.
* Don’t place MetaText in random positions; align them to a consistent margin grid.

---

### PillTag

**Do**

* Use PillTag sparingly to label things like “Data layer”, “Modeling”, or color swatches in visual-heavy sections.
* Keep them small and mostly white-on-lavender or dark-on-lavender to avoid visual noise.
* Align tags with other typographic elements, not floating independently.

**Don’t**

* Don’t build pill “clouds” or tag walls; that looks like generic SaaS feature tags.
* Don’t use PillTag as the main CTA style.
* Don’t mix too many accent colors inside tags; one accent per section is enough.

---

### HeroSection

**Do**

* Keep hero text strictly on the calm, dark side of the Giant M Horizon.
* Use only one primary CTA (“Contact us”) plus one subtle secondary anchor link.
* Let the M be the only strong visual in this section; no extra graphics.

**Don’t**

* Don’t add secondary illustrations, product mockups, or devices — that would read as SaaS.
* Don’t stack 3–4 CTAs or big buttons.
* Don’t center the hero text or cram content over the brightest part of the gradient.

---

### NarrativeSection

**Do**

* Treat it like a short essay: eyebrow, succinct title, then a couple of focused paragraphs.
* Use a single vertical rule and margin label to hint “chapter” structure.
* Keep backgrounds mostly flat with a hint of gradient at edges.

**Don’t**

* Don’t introduce card layouts or icons here; it’s meant to read as copy-first.
* Don’t alternate over-complicated layouts; this section should be calm and stable.
* Don’t mix too many font sizes; hierarchy should be clear and simple.

---

### SystemSection

**Do**

* Use the 3 structured items (Data / Automation / Quant Precision) as a textual “stack”.
* Add a subtle grid motif or horizontal lines under the whole block to suggest systemization.
* Place a MonoMetaText list on the right margin to reinforce the layered architecture.

**Don’t**

* Don’t turn the three items into **card tiles** with borders, icons, and shadows.
* Don’t add charts or fake dashboard screenshots — keep it abstract.
* Don’t rotate or distort the M; this section is about clarity and structure.

---

### PersonaSection (Rights Holders / Investors)

**Do**

* Give each persona section its own meta label (`Creators`, `Funds & Buyers`) to reinforce who it speaks to.
* Use 3 bullets max; keep them focused on outcomes and workflows.
* Apply separate subtle motifs (gradient ribbon vs M pattern) to differentiate the two.

**Don’t**

* Don’t copy-paste structure from a typical “Solutions by persona” grid (no icons per persona).
* Don’t use different color themes per persona; both live within the same palette with subtle variance.
* Don’t overload these sections with CTAs; one per section is enough.

---

### StepsSection & ContactSection

**Do**

* Present the steps as a simple, numbered list with monospaced indices.
* Keep the background light and calm — more like a document endnote than a sales pitch.
* End with a single clear action (“Contact us”) and plain-text email.

**Don’t**

* Don’t introduce a pricing table or plan comparison here.
* Don’t add an FAQ accordion; if questions arise, they can be part of conversation, not UI.
* Don’t visually shout; this section should feel like a thoughtful invitation.

## Self-check

**How this reflects the Figma-derived style, not a generic UI kit**

* The system leans heavily on **typography, margin notes, and the M/Soup motifs** instead of icons, illustrations, and cards. That mirrors your posters and Figma layouts, which are minimal but bold, with type doing most of the work.
* Components like **EyebrowLabel, MonoMetaText, NarrativeSection, SystemSection** are explicitly modeled as editorial building blocks (thesis, layers, chapters) rather than generic “feature card / testimonial / pricing” modules.

**Risk & mitigation**

* **Risk:** If someone later adds icons, boxes, or extra gradients into these components, they could slide back toward a generic SaaS design (feature cards, pastel tag clouds, dashboard hero).
* **Prevention:** Bake the constraints into the system docs:

  * no icons in Section headers or bullets,
  * limit gradients to **M and Soup backgrounds**,
  * enforce a maximum of one primary button per section.
    A short “anti-patterns” page with visual examples of “what *not* to do” will help keep future contributors on-brand.
